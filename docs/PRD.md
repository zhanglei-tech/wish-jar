## 1. 背景与目标

家里有一个 12 岁的孩子，希望通过"定目标 → 拆任务 → 完成打卡 → 获得积分 → 兑换约定奖励"的方式，把长期目标变成可执行、可看见的小步骤。

产品目标：

1. 让目标和奖励**看得见**：孩子随时能看到积分、等级、目标进度和心愿清单。
2. 让执行**足够轻**：家长记录一次完成不超过 5 秒，孩子打卡不超过 3 步。
3. 让规则**可追溯**：每一分积分都有来源和记录，家长可审核、可调整。
4. 数据**只在家里**：部署在自有 NAS，不依赖第三方云服务，照片和记录不出内网。

非目标：

- 不做面向公众的产品，不追求多家庭、多租户。
- 不做线上支付、真实货币充值、商城或社交功能；现金/实物奖励由家长线下兑现。
- 不替代家长的判断，审核和奖励兑现始终由家长决定。

## 2. 角色与使用场景

| 角色 | 说明 | 设备 | 主要诉求 |
|---|---|---|---|
| 家长 | 规则制定者与审核者，**2 位**（都能审核和管理） | 安卓手机 / PC | 快速设定目标、代记完成、审核打卡、管理奖励、看整体进度 |
| 孩子 | 12 岁，**没有自己的手机或平板** | 家庭共用设备（安卓平板/手机、PC），或由家长代操作 | 看到自己的积分和目标进度，对完成有成就感 |

### 2.1 三种使用模式（同一套功能，设置开关）

- **A. 家长代操作（主要方式，P0）**：孩子完成一件事后告诉家长，家长在自己手机上点"完成"并拍照/写备注，积分立即到账。孩子通过家长展示的屏幕看进度。
- **B. 共用设备自助（P0）**：家里的安卓平板/手机或 PC 打开应用，孩子选择自己的头像、输入 PIN，可以打卡、查看积分、查看奖励。是否进入"待家长审核"由成员设置决定。
- **C. 挂墙看板（P2，可选）**：一台常亮平板/电视作为家庭心愿罐看板，孩子和家长都能看到。

> 家里有可共用的设备，A、B 两种方式并存，**家长代记是主流程**。所有通知只发给家长（通知本身暂缓，见 FR-12）。

## 3. 核心流程

```
家长创建目标
   ↓
为目标添加阶段任务（一次性 / 每日 / 每周）
   ↓
孩子完成 → 打卡（可附照片/备注）  ── 或 ──  家长直接代记
   ↓
家长审核（可配置为免审核）
   ↓
积分入账（写入流水）→ 等级 / 连续打卡 / 目标进度更新
   ↓
孩子许愿（P1）→ 家长定价并上架奖励店
   ↓
孩子在奖励商店申请兑换 → 家长审批 → 扣积分 → 线下兑现 → 标记已兑现
   └─ 长期心愿：可先把可用积分锁定到该心愿，兑换时优先消耗锁定积分
```

## 4. 范围与优先级

### 4.1 MVP（P0，第一版必须可用）

1. 首次启动向导（家庭、家长、孩子）
2. 家庭成员与 PIN 登录
3. 目标与阶段任务管理
4. 打卡提交、家长审核、家长快速代记
5. 积分账本、余额 / 可用余额、等级、连续打卡
6. 奖励商店、兑换申请与审批、兑现（两步）
7. 孩子首页（心愿罐）
8. 家长看板（快速代记、待办、统计、积分调整、解锁储蓄）
9. 管理页（成员 / 目标 / 任务 / 奖励）
10. SQLite 数据持久化与每日备份
11. 群晖 Docker 单容器部署
12. 奖励兑换倍率（方案 B：`所需积分 = ceil(标价 × 倍率)`）
13. 长期心愿：进度、预计完成天数、锁定储蓄
14. 移动端响应式适配（Android Chrome 优先）

### 4.2 P1（体验完整）

1. 孩子许愿：孩子提交心愿，家长定价后上架奖励店
2. 统计报表：家长和孩子都可查看；周期可选周 / 月 / 季度 / 年；积分趋势、任务完成率、兑换记录；家长可导出 CSV（规则见 FR-22）
3. 任务连续完成奖励：同一每日任务在适用日连续完成达到任务阈值后，从达标当天起按任务设置比例额外奖励（规则见 FR-21）
4. 徽章体系：等级徽章（家长配置等级阈值）+ 目标成就徽章（目标完成自动获得，家长可自定义名称 / 图标；图标支持 emoji 或自定义图片；规则见 FR-23）
5. 家长配捐：家长为长期心愿手动或按比例配捐（规则见 FR-20.1）
6. 奖励专属任务：任务可关联到一个奖励，聚合展示专项进度；一个任务只能关联一个奖励（规则见 FR-24）
7. 分阶段目标与阶段成就：目标可选择按累计积分或累计完成次数推进，并配置多个阶段；每达到一个阶段自动获得阶段徽章（规则见 FR-25）

### 4.3 P2（锦上添花）

1. 通知：打卡提醒、晚间未完成汇总（渠道待定，暂缓）
2. 目标达成仪式：达成时首页庆祝（目标完成与成就徽章授予已在 P1 自动处理）
3. 家庭共同目标（全家一起攒分）
4. 挂墙看板模式（大屏、常亮）
5. AI 目标拆解（输入"学会骑自行车"，建议阶段任务与分值）
6. 亲友邀请查看
7. 成长报告打印 / 分享图片
8. PWA 安装到主屏幕 / 离线壳（当前内网使用为主，按需再做）
9. 任务模板与批量创建
10. 长期心愿里程碑 / 分段兑现（在奖励设置中自定义）
11. 多孩子周榜（默认关闭）

### 4.4 明确不做

- 多家庭 / 多租户 / 公开注册
- 线上支付、真实货币充值、积分交易；现金/实物奖励由家长线下兑现
- 社交、排行榜对外公开
- 自动识别照片内容或 AI 判卷
- 应用自身不做公网暴露方案；外网访问由群晖 DDNS 与反向代理提供

## 5. 功能需求

### FR-01 家庭成员管理（P0）

- 家长可添加成员，字段：姓名、头像（emoji）、角色（家长 / 孩子）、4 位数字 PIN、是否需要审核。
- 家长可修改成员资料、重置 PIN、启用/停用成员；不能停用自己。
- 至少保留一位可用家长。
- 验收：新增孩子后可在登录页看到头像并用 PIN 登录；停用后无法登录；非家长无法进入成员管理接口。

### FR-02 登录与身份（P0）

- 登录页展示所有启用成员的头像和名字，不分家长/孩子排序。
- 选择成员 → 输入 4 位数字 PIN → 进入对应界面。
- 会话有效期 30 天；Cookie 为 HttpOnly、SameSite=Lax。
- 孩子账号无法访问家长页面与家长接口；家长可访问全部页面。
- 验收：错误 PIN 有明确提示；孩子访问 `/parent` 被重定向；退出后回到登录页。

### FR-03 目标（P0）

- 家长为孩子创建目标：标题、emoji、描述、目标积分、可选起止日期。
- **P1**：目标图标支持 emoji 或上传自定义图片；有图片时优先展示图片，删除图片后回退 emoji。
- **P1**：目标可选择进度口径：累计积分（默认）或累计完成次数；口径创建后不可修改。
- **P1**：目标可设置完成徽章名称和图标，图标支持 emoji 或自定义图片，默认使用目标图标。
- **P1**：目标可配置多个阶段，每个阶段有阈值和阶段徽章；阶段规则见 FR-25。
- 目标状态：进行中 / 已完成 / 已归档。
- 目标进度 = 该目标下所有**已通过**任务所获得的积分之和。
- **P1 进度口径**：累计积分 = 目标下所有已通过任务的基础分 + 连续完成奖励；累计完成次数 = 目标下所有已通过提交的数量。
- **P1**：目标进度达到目标值（积分或完成次数）时自动标记为已完成，并授予完成徽章；家长手动标记完成同样授予完成徽章。
- **P1**：达到中间阶段时授予对应阶段徽章；达到目标值完成目标并授予完成徽章。
- 家长可编辑、完成、归档、删除目标；删除目标时保留任务，仅解除关联。
- **P1**：删除目标不回收已授予的完成徽章或阶段徽章；徽章保留授予时的名称 / 图标快照。
- 孩子只能查看自己的目标。
- 验收：创建目标后孩子首页可见；完成任务并审核通过后进度增加；删除目标后任务仍存在。
- **P1 验收**：达到目标自动完成并授予完成徽章；手动完成同样授予完成徽章；阶段目标达到中间阶段授予阶段徽章；完成徽章与阶段徽章均不重复；未自定义时徽章默认使用目标标题 / 图标；目标与徽章图片上传、显示和回退 emoji 正常。

### FR-04 任务（P0）

- 任务字段：标题、描述、积分（0–1000）、类型、所属目标（可空）、是否需照片、启用状态。
- **P1**：每日任务可设置适用星期、连续完成阈值（默认 7 天）和奖励比例（`0–100%`，默认 `25%`，`0` 表示关闭）；不设置截止时间。
- **P1**：任务可关联一个奖励（一个任务最多关联一个，见 FR-24）。
- 类型：
  - **一次性**：完成后不再出现新周期。
  - **每日**：每个适用自然日（按家庭时区）可完成一次；默认每天适用。
  - **每周**：每个自然周可完成一次。
- 同一任务在同一周期内最多一条有效提交记录。
- 家长可编辑、停用任务；停用后孩子端不再显示。
- MVP 任务只关联目标；任务关联奖励（专属任务）在 P1 实现（见 FR-24）。
- 验收：每日任务次日可再次打卡；同一天重复打卡被拒绝；每周任务跨周可再次打卡。

### FR-05 打卡提交（P0）

- 孩子或家长均可对任务发起提交，字段：备注（可选，≤200 字）、照片（可选或按任务必填）。
- 照片限制：JPG / PNG / WebP，单张 ≤ 5MB，存储于 NAS 数据卷。
- **免审核条件**：提交者为家长，或该孩子关闭了"需要审核"。
- 满足免审核时提交即通过并立即加分；否则进入待审核。
- 被驳回后，同一周期可重新提交，复用原记录。
- 验收：需照片任务未传照片时无法提交；重复提交给出明确提示；驳回后可重提。

### FR-06 审核（P0）

- 家长看板展示全部待审核提交，按提交时间排序。
- 通过：记录审核人、审核时间、评语，任务积分入账；每日任务满足连续完成条件时，同时结算连续完成奖励（见 FR-21）。
- 驳回：不入账，孩子端显示驳回原因。
- 同一条记录只能处理一次。
- 验收：通过后孩子余额增加且流水可见；驳回后余额不变；重复审核返回冲突提示。

### FR-07 积分账本（P0）

- 余额 = 该孩子全部积分流水之和，**不单独存余额字段**。
- **可用余额 = 余额 − 该孩子当前锁定的心愿储蓄**（见 FR-20）。
- 流水类型：任务获得、连续完成奖励、兑换扣除、家长调整。
- 每笔流水记录：变化值、类型、来源、备注、时间。
- 锁定 / 解锁心愿储蓄不写入积分流水，只写入储蓄记录；余额不变，可用余额变化。
- 家长可手动调整积分（正负均可），**备注必填**。
- 调整后的余额**不能为负数，也不能低于已锁定积分**；会导致可用余额为负的调整请求被拒绝。
- **等级** = 按家庭配置的等级阈值计算，默认 100 分/级；累计获得包含任务基础积分和连续完成奖励，不包含家长调整与配捐；兑换只扣余额，不影响等级；P1 起家长可配置阈值（见 FR-23）。
- **连续打卡** = 最近连续有已通过记录的自然日天数；今天尚未打卡时从昨天往前算。
- 验收：兑换后余额减少但等级不变；调整积分必须填写备注且出现在流水中；余额不会因重复审核重复增加，也不会被调整为负数或低于已锁定积分。

### FR-08 奖励商店（P0）

- 家长创建奖励：名称、emoji、描述、标价、单位（元 / 分钟 / 次 / 分）、兑换倍率、库存（`-1` 表示不限）。
- **所需积分 = ceil(标价 × 倍率)**；倍率默认 `1.0`，`>1` 表示比基准更贵，`<1` 表示更便宜。
- 固定积分奖励可直接把单位设为"分"、倍率设为 `1.0`，此时标价即积分。
- 孩子申请兑换时校验：奖励启用、库存不为 0；普通奖励要求**可用余额**足够，长期心愿要求**可用余额 + 该心愿锁定积分 + 有效配捐**足够。
- 申请生成"待审核"记录，**此时不扣分**；记录提交时的 `cost_points` 与倍率快照。
- 家长通过时再次校验可用余额（长期心愿同时校验锁定积分与有效配捐），按快照扣分、减库存；驳回不扣分。
- 通过后家长可标记"已兑现"（线下给到孩子）。
- 验收：可用余额不足无法申请（长期心愿按可用余额 + 锁定积分 + 配捐校验）；审批后余额正确；库存为 0 时无法兑换；驳回后余额不变；家长修改倍率不影响已提交的申请。
- 孩子提交的心愿经家长定价后，作为奖励出现在商店（见 FR-18）。

### FR-09 孩子首页（P0）

- 展示：头像与称呼、心愿罐可视化（积分/等级进度）、当前积分、可用积分、锁定积分、累计获得、连续天数。
- 今日任务列表：任务名、分值、类型、所属目标、状态（未完成 / 待确认 / 已完成 / 被驳回）、打卡入口；P1 展示该任务当前连续完成天数（按适用日计算）与奖励状态。
- **P1**：展示已获得等级徽章、目标成就徽章与下一等级进度；目标卡片展示阶段进度、阶段徽章与完成徽章；徽章墙按图标类型展示 emoji 或图片；可从个人页进入统计报表（见 FR-23 / FR-22 / FR-25）。
- 目标进度列表：进行中优先，显示已得 / 目标值（积分或完成次数）和进度条。

- 验收：完成打卡后刷新可见状态与积分变化；驳回原因可见；每日任务次日恢复为未完成。

### FR-18 孩子许愿（P1）

- 家长看到待处理心愿后，可设置标价、单位、倍率、库存并上架为奖励，或驳回并填写原因。
- 上架后的心愿与普通奖励一致，进入奖励商店兑换流程。
- 孩子可查看自己提交的心愿及状态（待定价 / 已上架 / 已驳回）。
- 验收：孩子提交后家长端出现待处理项；家长定价上架后孩子端可见并可兑换；驳回原因可见。

### FR-19 奖励兑换倍率（P0）

- 采用方案 B（成本倍率）：`所需积分 = ceil(标价 × 倍率)`。
- 倍率默认 `1.0`，创建奖励时灵活设置：
  - `1.0` 为基准（如电脑：5000 元 × 1.0 = 5000 分）；
  - `>1` 表示该奖励比基准更贵（如现金：100 元 × 1.5 = 150 分）；
  - `<1` 表示比基准更便宜（如书：100 元 × 0.8 = 80 分）；
  - 游戏时间等同理，如 60 分钟 × 1.2 = 72 分。
- 倍率按奖励单独设置，不做全局固定值；不引入奖励分类或分类默认倍率，避免增加配置复杂度。
- 孩子端展示最终积分价与倍率含义（如“100 元 → 150 分，1.5 倍”）；家长端展示该奖励的实际支出或时间成本。
- 若孩子有进行中的长期心愿，兑换其他奖励时按该心愿的倍率提示影响（如电脑 1.0 时，“换 100 元现金需要 150 分；这 150 分留给电脑值 150 元”）。
- 兑换申请提交时快照 `cost_points` 与倍率，之后家长修改倍率不影响已提交的申请。
- 验收：修改倍率后新申请按新价格；已提交申请按快照价格；孩子端与家长端显示一致。

### FR-20 长期心愿与锁定储蓄（P0）

- 家长可将奖励标记为“长期心愿”；高积分奖励（如 5000 元电脑）建议标记为长期心愿。
- MVP 的长期心愿只做**进度、预计完成天数、锁定储蓄**；家长配捐、奖励专属任务后置 P1（配捐规则见 FR-20.1）；里程碑 / 分段兑现后置 P2。
- 长期心愿详情展示：目标积分、已存入、剩余积分（目标 − 已存入）、进度条、预计完成天数。
- **预计完成天数**：取最近 14 天（长期心愿优先 30 天，数据不足时按实际天数）的日均获得积分；`预计天数 = ceil(剩余积分 ÷ 日均)`。数据不足 3 天时提示“再记录几天就能预估”；日均为 0 时提示“完成一个任务就能开始预估”。
- 预计天数用“约 X 周 / X 个月”展示，不承诺精确日期；高积分长期心愿可能持续数月到一年以上，MVP 用进度、预计天数和锁定储蓄维持动机，P1 增加配捐（见 FR-20.1），里程碑 / 分段兑现后置 P2。
- **锁定储蓄**：孩子可把可用积分存入某个长期心愿；存入后不可用于其他奖励。
- `可用余额 = 余额 − 已锁定积分`；锁定 / 解锁不改变积分余额，只改变可用余额，并写入储蓄记录。
- **解锁由家长操作**；孩子不能自行解锁。MVP 不做孩子申请解锁的流程。
- 兑换长期心愿时，优先消耗该心愿的锁定积分，其次消耗有效配捐，不足部分再使用可用积分；兑换成功后对应锁定记录标记为已兑换；锁定积分超过应付积分的部分退回可用余额，配捐超过应付积分的部分作废。
- 删除或停用长期心愿前必须先释放全部锁定积分，否则拒绝操作。
- 验收：锁定后可用余额减少、余额不变；其他奖励无法使用锁定积分；解锁后可用余额恢复；兑换长期心愿时锁定积分与配捐按顺序正确消耗；预计天数在数据不足时有明确提示。

### FR-20.1 家长配捐（P1）

配捐是家长绑定到某个长期心愿的专用支持额度，不是孩子的通用积分。

**记账口径**

- 配捐不进入孩子余额，不写 `point_transactions`，不能用于其他奖励。
- 不计入“累计获得”，不影响等级；等级仍只按任务相关积分累计（基础分 + 连续完成奖励）。
- 配捐不设上限；兑换时只使用到应付积分，超出部分作废。

**来源**

- 手动配捐：家长在长期心愿详情中主动添加一笔配捐，金额为正整数，可填写备注；未消耗前可撤销。
- 自动配捐：家长可为长期心愿设置自动配捐比例（`0–100%`，默认 `0` 表示关闭）。自动配捐不逐笔生成记录，而是在兑换时按孩子当前有效锁定金额一次性计算：
  `自动配捐 = min(floor(当前锁定 × 比例), max(0, 应付积分 − 当前锁定 − 手动配捐))`。
- 自动配捐只与“当前锁定了多少”有关，与分几次锁定无关；释放锁定后，自动配捐的预计金额和最终结算金额都会减少。
- 修改或关闭比例会立即影响之后的预览与兑换；兑换完成后按当时比例快照生成一条已使用的自动配捐记录，后续改比例不影响已完成兑换。
- 手动配捐由家长主动添加，不要求孩子先锁定；家长可以只支持一部分，也可以覆盖全部应付积分。

**进度与兑换**

- 心愿已存入 = 孩子在该心愿的 active 锁定积分 + 手动 active 配捐 + 预计自动配捐；剩余积分 = `max(0, 应付积分 − 已存入)`。
- 预计自动配捐按当前锁定金额实时计算，并封顶到扣除孩子锁定和手动配捐后的剩余应付积分；孩子锁定超过所需金额时，不会显示用不上的配捐。
- 预计完成天数按扣除有效配捐后的剩余积分估算。
- 兑换时先按当前锁定金额结算自动配捐，再与手动配捐合并为“配捐池”；抵扣顺序为：孩子锁定积分 → 配捐池 → 可用余额。
- 孩子锁定积分超过应付积分的部分退回可用余额；配捐池超过应付积分的部分作废，不找零、不转为余额。
- 已被兑换消耗的配捐标记为已使用；未消耗部分随兑换完成作废。

**撤销与作废**

- 手动配捐未消耗时可撤销；已消耗或已作废的不可撤销，保留记录用于审计。
- 自动配捐没有“未消耗记录”可撤销；家长通过修改或关闭比例控制后续结算，已完成兑换的自动配捐不可撤销。
- 孩子主动放弃心愿（若提供该操作）、家长删除或停用该长期心愿时，所有未消耗的手动配捐作废；自动配捐随之消失。
- 释放孩子的锁定积分会降低自动配捐，但不影响已生成的手动配捐。

**展示**

- 孩子端长期心愿详情显示“自己存入 X / 家长支持 Y”，其中 Y 包含手动配捐和预计自动配捐；家长端显示手动配捐明细与自动配捐比例。
- 配捐不影响余额、可用余额、累计获得、等级和连续打卡的展示口径。

**验收**

- 配捐后孩子余额、累计获得、等级不变；其他奖励不能使用配捐。
- 自动配捐按当前锁定金额 × 比例计算，只在兑换时结算；释放锁定后自动配捐减少，手动配捐不变。
- 兑换时按“锁定 → 配捐池 → 可用余额”扣减；多余锁定退回可用余额，多余配捐作废。
- 删除/停用长期心愿或孩子放弃时，未消耗手动配捐作废；自动配捐消失。
- 手动配捐未消耗可撤销，已消耗/已作废不可撤销；自动配捐通过修改/关闭比例控制。

### FR-21 任务连续完成奖励（P1）

- 仅每日任务适用；每周任务、一次性任务不产生连续完成奖励。
- 每个任务可单独设置：
  - 适用星期（默认每天，多选）；只有适用日展示任务并计入连续完成。
  - 连续完成阈值（`1–30` 天，默认 `7` 天）。
  - 奖励比例（`0–100%`，默认 `25%`，`0` 表示关闭）。
- 不设置截止时间；任务在适用日的任意时间完成，是否计入由审核/代记结果决定。
- 连续完成天数按该任务在**适用日**的已通过提交计算；非适用日直接跳过，不算中断；家长代记也算完成，待审核、驳回不计入。
- 连续完成天数达到阈值的**当天**起，每次继续连续完成都额外奖励 `ceil(任务基础积分 × 比例)`；不再等到第 8 天。
- 奖励按任务基础积分计算，不叠加、不复利；例如 10 分任务、阈值 7 天、比例 25%，第 7 个适用日起每次奖励 3 分。
- 奖励写入积分流水（类型“连续完成奖励”），计入余额、可用余额、累计获得和等级；不影响锁定储蓄。
- 连续完成中断后重新从第 1 天计算；任务停用或类型变更后重新计算。
- 修改适用星期后，连续完成天数重新计算；修改阈值或比例后，从下一次审批开始按新规则判断，不追溯已结算记录。
- 奖励在审批通过时按当时已通过的连续记录结算；后续补审不回溯修改已结算记录。
- 孩子端任务卡片展示当前连续完成天数与奖励状态；家长端任务编辑展示适用星期、阈值和比例。
- 示例：周一至周四作业任务，阈值 7 天。第 1 周完成 4 天；第 2 周周一 5 天、周二 6 天、周三 7 天，周三当天开始获得奖励。周末跳过，不中断连续。
- 验收：达到阈值当天开始奖励；阈值、比例和适用星期按任务设置；非适用日跳过；中断后重置；比例为 0 时关闭；每周/一次性任务无奖励；奖励后累计获得和等级包含奖励分。

### FR-22 统计报表（P1）

- 家长和孩子都可查看；孩子只能看自己的数据，家长可查看孩子的数据。
- 统计周期：周（ISO 周）、月、季度、年；默认本周；按家庭时区计算。
- 指标：
  - 积分趋势：周期内任务获得、连续完成奖励、兑换扣除、家长调整后的积分变化。
  - 任务完成率：周期内已通过提交数 ÷ 应完成次数；每日任务按适用日计，每周任务按周计，一次性任务按创建当期计 1 次；任务创建前的日期不计入。
  - 兑换记录：兑换次数、消耗积分与状态分布。
- 家长可导出 CSV；孩子端不提供导出。
- 空数据展示空状态，不把“没有记录”显示成 0 分趋势。
- 验收：周期切换数据正确；孩子无法查看其他孩子的数据；CSV 内容与页面一致；统计口径与积分流水、打卡记录一致。

### FR-23 徽章体系（P1）

- 徽章分两类：等级徽章与目标成就徽章；两类徽章分开展示，均不发积分，不影响余额、可用余额、锁定储蓄和兑换。
- 成就徽章图标支持 emoji 或自定义图片；等级徽章使用系统图标，不开放自定义图片。

**等级徽章**

- Lv.1 为初始等级，不单独发徽章；Lv.2 起每个等级对应一个系统徽章。
- 家长可配置 Lv.2–Lv.20 的累计积分要求；Lv.1 固定为 0；阈值必须严格递增。默认每级 100 分（Lv.2 = 100，Lv.3 = 200…）。
- 等级按累计获得积分计算：任务基础分 + 连续完成奖励，不包含家长调整与配捐；取达到的最高等级。
- 达到等级阈值自动获得对应徽章；徽章永久保留，不重复发放。
- 修改等级阈值后，当前等级按新配置重新计算；已获得徽章不回收；首次配置或调低阈值时按当前等级补发已达成徽章，后续新达到的等级也补发。
- 兑换只扣余额，不降级；因阈值调整导致的等级变化不属于兑换降级。

**目标成就徽章**

- 不单独设置“成就”模块：目标完成徽章与阶段徽章统称目标成就徽章；阶段规则见 FR-25。
- 每个目标有一枚完成徽章；配置阶段时，每个阶段额外有一枚阶段徽章。家长创建或编辑目标时可自定义名称与图标，图标支持 emoji 或自定义图片，默认使用目标图标。
- 自定义图片限制：JPG / PNG / WebP，单张 ≤ 2MB；建议 1:1 展示，前端按方形容器裁切、不拉伸；仅存 NAS 本地，使用随机文件名；API 仅返回受控访问地址，不返回内部文件路径。
- 图标上传、替换、删除仅家长可操作，孩子只能查看。
- 有图片时优先展示图片；删除图片或未上传时回退 emoji。
- 目标进度达到目标值时自动标记为已完成并授予完成徽章；家长手动标记完成同样授予完成徽章。
- 同一完成徽章每个目标一枚，同一阶段徽章每个阶段一枚；目标重新打开、修改目标值或阶段、归档或删除都不重复授予，也不回收已授予徽章。
- 徽章授予时保存名称与图标快照；图片徽章复制为徽章自有文件，后续修改或删除目标图标不影响已获得徽章。
- 目标卡片展示阶段进度、阶段徽章与完成徽章；孩子端徽章墙将“等级徽章”和“目标成就徽章”分开展示。
- 验收：完成徽章与阶段徽章均可正确授予且不重复；目标自动 / 手动完成都授予完成徽章；阶段规则符合 FR-25；修改或删除目标不回收；家长自定义名称 / 图标生效且默认取目标标题 / 图标；图片上传、显示、回退 emoji 与徽章图标快照符合规则；仅家长可修改图标且 API 不暴露内部路径；两类徽章分开展示；徽章不影响余额、可用余额和锁定储蓄。

### FR-24 奖励专属任务（P1）

- 任务可关联一个奖励（`reward_id`，可空）；一个任务最多关联一个奖励，一个奖励可关联多个任务。
- 只有启用中的奖励可选；任务编辑时可更换或解除关联。
- 奖励详情展示关联任务列表，以及这些任务累计获得的积分（任务基础分 + 连续完成奖励）。
- 该进度仅用于展示，不形成独立余额，不自动锁定，也不影响兑换顺序。
- 关联任务完成后仍按普通任务计分，孩子可将积分用于任何奖励。
- 奖励停用或删除时解除任务关联。
- 验收：一个任务不能关联多个奖励；奖励详情聚合正确；专属任务积分不重复计入余额；解除关联后进度更新。

### FR-25 分阶段目标与阶段成就（P1）

**进度口径**

- 目标创建时选择进度口径：累计积分（默认）或累计完成次数；创建后不可修改，需要更换时新建目标。
- 累计积分：目标下所有已通过任务的基础分 + 连续完成奖励，不含家长调整与配捐。
- 累计完成次数：目标下所有已通过提交的数量；每一条已通过提交计 1 次，待审核和已驳回不计入。
- 系统不判断具体完成时刻；“按时完成”由家长审核时判断，不重新引入任务截止时间。
- 目标进度按当前关联任务实时计算；任务移出目标后进度可能减少，但已授予的阶段徽章和目标完成状态不回退。

**阶段配置**

- 目标可配置 0–10 个中间阶段；不配置阶段时按单一目标值和完成徽章执行。
- 每个阶段包含阈值、阶段徽章名称、阶段徽章图标；阶段阈值必须大于 0、严格递增，且小于目标值。
- 修改目标值后，所有阶段阈值仍需严格小于目标值；不满足时先调整或删除相应阶段。
- 阶段阈值单位与目标进度口径一致：积分口径用积分，完成次数口径用次数。
- 阶段徽章图标支持 emoji 或自定义图片，限制和快照规则与 FR-23 一致；未自定义时默认使用目标图标，名称默认使用“目标标题 · 阶段阈值”。
- 阶段阈值、名称和图标仅家长可配置。

**授予与编辑**

- 每条提交通过后重新计算目标进度；跨过阶段阈值时授予对应阶段徽章，一次跨过多个阶段则补发全部已达成阶段徽章。
- 达到目标值时自动完成目标并授予完成徽章；完成徽章仍使用目标自身的徽章名称和图标配置。
- 阶段徽章与完成徽章相互独立，均永久保留、不重复授予、不发积分，不影响余额、可用余额、累计获得和等级。
- 家长手动标记完成只授予完成徽章；未达到的阶段不补发阶段徽章。
- 目标未完成时，新增阶段或调低阶段阈值后，按当前进度补发已达成但未授予的阶段徽章；调高阈值不回收已授予徽章。
- 目标完成后不再补发阶段徽章；完成时未达到的阶段不补发。
- 删除阶段不回收已授予的阶段徽章，后续也不再产生该阶段的新徽章。
- 修改目标值、阶段、关联任务、归档或删除目标，都不回收已授予的阶段徽章或完成徽章。
- 目标已完成后再调高目标值，不恢复为进行中，也不重复授予完成徽章。

**展示与边界**

- 目标卡片展示当前进度、阶段节点、已达成阶段和下一阶段；孩子端徽章墙在“目标成就徽章”内按目标分组展示阶段徽章与完成徽章。
- 阶段徽章只做成就展示，不发放积分、不生成阶段奖励、不自动解锁奖励，也不参与奖励分段兑现；奖励里程碑仍在 P2。
- 首版阶段进度只支持累计积分和累计完成次数，不提供“连续完成天数”口径；每日任务的连续完成仍按 FR-21 的连续完成奖励处理。

**验收**

- 积分口径：目标值 600 分、阶段 300 分；达到 300 分授予阶段徽章，达到 600 分完成目标并授予完成徽章。
- 完成次数口径：目标值 60 次、阶段 30 次；第 30 条通过提交授予阶段徽章，第 60 条完成目标并授予完成徽章。
- 一次从 0 跨到 60 次时，30 次和 60 次对应的徽章都正确授予且不重复。
- 阶段阈值严格递增且小于目标值；最多 10 个阶段；进度口径创建后不可修改。
- 调低阈值或新增阶段时补发已达成的阶段徽章；调高、删除阶段或删除目标不回收已授予徽章。
- 手动完成只授予完成徽章，不补发未达到的阶段徽章；目标完成后不再补发阶段徽章。
- 修改目标值后，阶段阈值仍严格小于目标值，否则保存失败。
- 阶段徽章和完成徽章不影响余额、可用余额、累计获得和等级。

## 6. 关键业务规则汇总

| 规则 | 定义 |
|---|---|
| 积分余额 | 流水求和，实时计算 |
| 等级 | 按家庭等级阈值计算，默认 100 分/级；累计获得 = 任务基础分 + 连续完成奖励；P1 可配置（见 FR-23）；兑换不降级 |
| 任务连续完成奖励（P1） | 仅每日任务；可设适用星期与阈值（默认 7 天）；在适用日连续完成达到阈值的当天起每次额外 `ceil(基础分 × 任务比例)`，非适用日跳过，计入余额、累计获得和等级 |
| 分阶段目标（P1） | 目标创建时选累计积分或累计完成次数；可配 0–10 个阶段，阈值严格递增且小于目标值；达到阶段授予阶段徽章，达到目标值完成并授予完成徽章 |
| 成就徽章（P1） | 每个目标一枚完成徽章，每个阶段一枚阶段徽章；自动授予、永久保留、不重复、不发积分；修改或删除目标、阶段不回收 |
| 审核 | 家长代操作或成员关闭审核时免审 |
| 快速代记 | 家长从看板一键完成，立即通过并加分 |
| 手动调整 | 备注必填；调整后余额不能为负，且不能低于已锁定积分 |
| 首次启动 | 初始化向导，不预置虚构成员 |
| 周期键 | 每日 = 本地日期（仅适用日）；每周 = ISO 周；一次性 = `once` |
| 驳回重提 | 复用同周期记录，重置为待审核 |
| 兑换扣分时机 | 家长审批通过时，而非孩子申请时 |
| 奖励倍率 | 方案 B：`所需积分 = ceil(标价 × 倍率)`；1.0 为基准，>1 更贵，<1 更便宜 |
| 倍率快照 | 兑换申请提交时记录 `cost_points` 与倍率，之后改价不影响已提交申请 |
| 可用余额 | `余额 − 已锁定心愿储蓄` |
| 锁定储蓄 | 只用于对应长期心愿；解锁由家长操作；兑换时优先消耗 |
| 家长配捐（P1） | 心愿专用额度；不进余额、不写流水、不计累计/等级；兑换按“锁定 → 配捐池 → 可用余额”；手动未消耗可撤销，心愿终止作废 |
| 自动配捐（P1） | 比例 `0–100%`，默认关闭；兑换时按当前锁定金额计算并封顶到剩余应付；释放锁定会降低自动配捐；不按次生成、不记水位 |
| 预计天数 | 最近 14 天日均（长期优先 30 天，不足按实际）；`ceil(剩余 ÷ 日均)` |
| 库存 | `-1` 不限；审批通过时减 1 |
| 照片 | JPG/PNG/WebP ≤ 5MB，仅存本地 |
| 图标（P1） | 目标、阶段徽章与完成徽章支持 emoji 或 JPG/PNG/WebP 图片，单张 ≤ 2MB；图片优先、emoji 回退；徽章授予时固化图标快照 |
| 时区 | 家庭时区，默认 `Asia/Shanghai` |
| PIN | 固定 4 位数字，scrypt 哈希存储 |

| 4 | 首次启动 | 使用初始化向导；不预置虚构成员；开发环境保留示例数据 |
| 5 | 等级与连续打卡 | 默认 100 分/级；P1 家长可配置 Lv.2–Lv.20 的累计积分要求（见 FR-23）；总连续打卡只展示、不加成；P1 增加按每日任务计算的连续完成奖励（见 FR-21） |
| 6 | 每日/每周任务 | 不设截止时间；每日 0 点、每周一 0 点重置；P1 每日任务可设适用星期；晚间提醒随通知归 P2 |
| 7 | 手动调整积分 | 备注必填；调整后余额不能为负，且不能低于已锁定积分 |
| 8 | 家长人数 | 2 位，均可审核和管理 |
| 9 | 通知 | 渠道未定，第一版不做（暂缓到 P2） |
| 10 | 外网访问 | 偶尔需要（探亲、旅游）；**群晖自带 DDNS，无需额外开发**；设备以安卓手机/平板和 PC 为主 |
| 11 | 奖励倍率 | 采用**方案 B（成本倍率）**：`所需积分 = ceil(标价 × 倍率)`；1.0 为基准，>1 更贵，<1 更便宜 |
| 12 | 高积分奖励 | MVP 先做长期心愿的进度、预计天数、锁定储蓄；家长配捐、奖励专属任务后置 P1；里程碑 / 分段兑现后置 P2 |
| 13 | 锁定储蓄 | 做；锁定积分不可用于其他奖励；解锁由家长操作；兑换长期心愿时优先消耗锁定 |
| 14 | 倍率设置 | 创建奖励时灵活设置；字段默认 `1.0`，但不做全局固定倍率；示例“电脑 1.0、现金 1.5、游戏 1.2”仅作参考 |
| 15 | PWA | 当前不做；更多是家里内网访问，直接使用响应式网页；PWA 放到 P2 按需再做 |
| 16 | 家长配捐（P1） | 心愿专用额度：不进余额、不写流水、不计累计/等级；不限上限；手动配捐随时可加、未消耗可撤销；自动配捐按奖励比例在兑换时以当前锁定金额结算，释放锁定会降低自动配捐；兑换按“孩子锁定 → 配捐池 → 可用余额”；心愿终止时未消耗手动配捐作废 |
| 17 | 任务连续完成奖励（P1） | 仅每日任务；可设适用星期、阈值（默认 7 天）和比例（默认 25%）；在适用日连续完成达到阈值的当天起额外奖励；按基础分向上取整，不叠加；计入余额、累计获得和等级；非适用日跳过，中断后重置 |
| 18 | 徽章体系（P1） | 等级徽章按等级阈值自动获得，使用系统图标；目标成就徽章包括完成徽章与阶段徽章，自动获得、永久保留、不发积分；名称 / 图标可自定义（emoji 或图片） |
| 19 | 统计报表（P1） | 家长和孩子都可查看；周期周 / 月 / 季度 / 年；孩子仅看自己的数据，家长可导出 CSV |
| 20 | 奖励专属任务（P1） | 一个任务最多关联一个奖励，一个奖励可关联多个任务；进度仅展示，不形成独立余额、不自动锁定 |
| 21 | P1 范围调整 | 任务模板与批量创建、长期心愿里程碑 / 分段兑现、多孩子周榜移到 P2 |
| 22 | 目标与成就合并（P1） | 不单独做成就模块；目标完成即达成成就；完成徽章与阶段徽章自动授予；同一目标 / 阶段不重复授予，删除目标不回收 |
| 23 | 图标自定义（P1） | 目标、阶段徽章与完成徽章支持 emoji 或自定义图片；JPG/PNG/WebP ≤2MB；图片优先、emoji 回退；徽章授予时固化图片快照；等级徽章仍用系统图标 |
| 24 | 分阶段目标（P1） | 目标创建时选累计积分或累计完成次数；可配 0–10 个阶段，阈值严格递增且小于目标值；达到阶段授予阶段徽章，达到目标值完成并授予完成徽章；手动完成只授予完成徽章；阶段徽章不发积分、不参与奖励分段兑现 |
| C | 新增需求 | 孩子许愿（P1）；家长快速代记（P0） |

### 12.2 后续可调整（不阻塞 MVP）

以下不是 MVP 阻塞项，开发中按当前默认值实现，后续根据实际使用调整。

- 孩子许愿的具体交互：图片与 emoji 的选择方式、家长定价时是否需要写理由、单次心愿数量限制。
- 通知渠道（以后需要时再定）。
- 奖励倍率的取值范围与校验规则：实现时先做基本限制（如 `0.1–5.0`），实际使用后再调整。
- 预计完成天数的数据窗口：先用 14 天（长期 30 天），根据实际数据表现调整。
- 长期心愿里程碑 / 分段兑现：P2 再评估，且应放在奖励设置中自定义。
- 家长配捐：自动配捐比例先按 `0–100%` 实现；是否要求孩子至少承担一定自付比例、是否增加单笔或总额上限，P1 上线后按实际使用评估。
- 储蓄解锁流程：MVP 只做家长直接解锁；是否增加孩子申请 + 家长确认，后续再定。
- 等级数量上限 P1 先支持 Lv.1–Lv.20；等级徽章使用系统图标；目标与成就徽章支持 emoji 或自定义图片（JPG/PNG/WebP ≤2MB）。是否支持 SVG/GIF、在线裁剪与奖励图标自定义，P1 上线后按需评估。
- 分阶段目标首版只支持累计积分和累计完成次数，不提供连续完成天数口径；阶段数量上限先按 10 个实现。阶段积分奖励、阶段解锁奖励、阶段兑换后续再评估。
- 统计报表的具体指标与图表形式，P1 上线后按实际使用调整。
- 奖励专属任务进度是否包含连续完成奖励，先按包含奖励分统计。
- 其他想法已记录，按优先级排期。
