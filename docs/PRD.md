## 1. 背景与目标

家里有一个 12 岁的孩子，希望通过"定目标 → 拆任务 → 完成打卡 → 获得积分 → 兑换约定奖励"的方式，把长期目标变成可执行、可看见的小步骤。

产品目标：

1. 让目标和奖励**看得见**：孩子随时能看到积分、等级、目标进度和心愿清单。
2. 让执行**足够轻**：家长记录一次完成不超过 5 秒，孩子打卡不超过 3 步。
3. 让规则**可追溯**：每一分积分都有来源和记录，家长可审核、可调整。
4. 数据**只在家里**：部署在自有 NAS，不依赖第三方云服务，照片和记录不出内网。

非目标：

- 不做面向公众的产品，不追求多家庭、多租户。
- 不做线上支付、真实货币充值、商城或社交功能；现金/实物奖励由家长线下兑现。
- 不替代家长的判断，审核和奖励兑现始终由家长决定。

## 2. 角色与使用场景

| 角色 | 说明 | 设备 | 主要诉求 |
|---|---|---|---|
| 家长 | 规则制定者与审核者，**2 位**（都能审核和管理） | 安卓手机 / PC | 快速设定目标、代记完成、审核打卡、管理奖励、看整体进度 |
| 孩子 | 12 岁，**没有自己的手机或平板** | 家庭共用设备（安卓平板/手机、PC），或由家长代操作 | 看到自己的积分和目标进度，对完成有成就感 |

### 2.1 三种使用模式（同一套功能，设置开关）

- **A. 家长代操作（主要方式，P0）**：孩子完成一件事后告诉家长，家长在自己手机上点"完成"并拍照/写备注，积分立即到账。孩子通过家长展示的屏幕看进度。
- **B. 共用设备自助（P0）**：家里的安卓平板/手机或 PC 打开应用，孩子选择自己的头像、输入 PIN，可以打卡、查看积分、查看奖励。是否进入"待家长审核"由成员设置决定。
- **C. 挂墙看板（P2，可选）**：一台常亮平板/电视作为家庭心愿罐看板，孩子和家长都能看到。

> 家里有可共用的设备，A、B 两种方式并存，**家长代记是主流程**。所有通知只发给家长（通知本身暂缓，见 FR-12）。

## 3. 核心流程

```
家长创建目标
   ↓
为目标添加阶段任务（一次性 / 每日 / 每周）
   ↓
孩子完成 → 打卡（可附照片/备注）  ── 或 ──  家长直接代记
   ↓
家长审核（可配置为免审核）
   ↓
积分入账（写入流水）→ 等级 / 连续打卡 / 目标进度更新
   ↓
孩子许愿（P1）→ 家长定价并上架奖励店
   ↓
孩子在奖励商店申请兑换 → 家长审批 → 扣积分 → 线下兑现 → 标记已兑现
   └─ 长期心愿：可先把可用积分锁定到该心愿，兑换时优先消耗锁定积分
```

## 4. 范围与优先级

### 4.1 MVP（P0，第一版必须可用）

1. 首次启动向导（家庭、家长、孩子）
2. 家庭成员与 PIN 登录
3. 目标与阶段任务管理
4. 打卡提交、家长审核、家长快速代记
5. 积分账本、余额 / 可用余额、等级、连续打卡
6. 奖励商店、兑换申请与审批、兑现（两步）
7. 孩子首页（心愿罐）
8. 家长看板（快速代记、待办、统计、积分调整、解锁储蓄）
9. 管理页（成员 / 目标 / 任务 / 奖励）
10. SQLite 数据持久化与每日备份
11. 群晖 Docker 单容器部署
12. 奖励兑换倍率（方案 B：`所需积分 = ceil(标价 × 倍率)`）
13. 长期心愿：进度、预计完成天数、锁定储蓄
14. 移动端响应式适配（Android Chrome 优先）

### 4.2 P1（体验完整）

1. 孩子许愿：孩子提交心愿，家长定价后上架奖励店
2. 统计报表：积分趋势、任务完成率、兑换记录、CSV 导出
3. 任务模板与批量创建
4. 徽章 / 成就体系
5. 多孩子周榜（默认关闭）
6. 长期心愿增强：家长配捐、目标日期、里程碑 / 分段兑现
7. 奖励专属任务：任务可关联到某个奖励，聚合展示专项进度
8. 奖励分类与分类默认倍率

### 4.3 P2（锦上添花）

1. 通知：打卡提醒、晚间未完成汇总（渠道待定，暂缓）
2. 目标达成仪式：达成时首页庆祝，由家长确认完成
3. 家庭共同目标（全家一起攒分）
4. 挂墙看板模式（大屏、常亮）
5. AI 目标拆解（输入"学会骑自行车"，建议阶段任务与分值）
6. 亲友邀请查看
7. 成长报告打印 / 分享图片
8. PWA 安装到主屏幕 / 离线壳（当前内网使用为主，按需再做）

### 4.4 明确不做

- 多家庭 / 多租户 / 公开注册
- 线上支付、真实货币充值、积分交易；现金/实物奖励由家长线下兑现
- 社交、排行榜对外公开
- 自动识别照片内容或 AI 判卷
- 应用自身不做公网暴露方案；外网访问由群晖 DDNS 与反向代理提供

## 5. 功能需求

### FR-01 家庭成员管理（P0）

- 家长可添加成员，字段：姓名、头像（emoji）、角色（家长 / 孩子）、4 位数字 PIN、是否需要审核。
- 家长可修改成员资料、重置 PIN、启用/停用成员；不能停用自己。
- 至少保留一位可用家长。
- 验收：新增孩子后可在登录页看到头像并用 PIN 登录；停用后无法登录；非家长无法进入成员管理接口。

### FR-02 登录与身份（P0）

- 登录页展示所有启用成员的头像和名字，不分家长/孩子排序。
- 选择成员 → 输入 4 位数字 PIN → 进入对应界面。
- 会话有效期 30 天；Cookie 为 HttpOnly、SameSite=Lax。
- 孩子账号无法访问家长页面与家长接口；家长可访问全部页面。
- 验收：错误 PIN 有明确提示；孩子访问 `/parent` 被重定向；退出后回到登录页。

### FR-03 目标（P0）

- 家长为孩子创建目标：标题、emoji、描述、目标积分、可选起止日期。
- 目标状态：进行中 / 已完成 / 已归档。
- 目标进度 = 该目标下所有**已通过**任务所获得的积分之和。
- 家长可编辑、完成、归档、删除目标；删除目标时保留任务，仅解除关联。
- 孩子只能查看自己的目标。
- 验收：创建目标后孩子首页可见；完成任务并审核通过后进度增加；删除目标后任务仍存在。

### FR-04 任务（P0）

- 任务字段：标题、描述、积分（0–1000）、类型、所属目标（可空）、是否需照片、启用状态。
- 类型：
  - **一次性**：完成后不再出现新周期。
  - **每日**：每个自然日（按家庭时区）可完成一次。
  - **每周**：每个自然周可完成一次。
- 同一任务在同一周期内最多一条有效提交记录。
- 家长可编辑、停用任务；停用后孩子端不再显示。
- MVP 任务只关联目标；任务关联奖励（专属任务）在 P1 评估。
- 验收：每日任务次日可再次打卡；同一天重复打卡被拒绝；每周任务跨周可再次打卡。

### FR-05 打卡提交（P0）

- 孩子或家长均可对任务发起提交，字段：备注（可选，≤200 字）、照片（可选或按任务必填）。
- 照片限制：JPG / PNG / WebP，单张 ≤ 5MB，存储于 NAS 数据卷。
- **免审核条件**：提交者为家长，或该孩子关闭了"需要审核"。
- 满足免审核时提交即通过并立即加分；否则进入待审核。
- 被驳回后，同一周期可重新提交，复用原记录。
- 验收：需照片任务未传照片时无法提交；重复提交给出明确提示；驳回后可重提。

### FR-06 审核（P0）

- 家长看板展示全部待审核提交，按提交时间排序。
- 通过：记录审核人、审核时间、评语，任务积分入账。
- 驳回：不入账，孩子端显示驳回原因。
- 同一条记录只能处理一次。
- 验收：通过后孩子余额增加且流水可见；驳回后余额不变；重复审核返回冲突提示。

### FR-07 积分账本（P0）

- 余额 = 该孩子全部积分流水之和，**不单独存余额字段**。
- **可用余额 = 余额 − 该孩子当前锁定的心愿储蓄**（见 FR-20）。
- 流水类型：任务获得、兑换扣除、家长调整。
- 每笔流水记录：变化值、类型、来源、备注、时间。
- 锁定 / 解锁心愿储蓄不写入积分流水，只写入储蓄记录；余额不变，可用余额变化。
- 家长可手动调整积分（正负均可），**备注必填**。
- 调整后的余额**不能为负数，也不能低于已锁定积分**；会导致可用余额为负的调整请求被拒绝。
- **等级** = 累计获得积分 ÷ 100 取整 + 1；兑换只扣余额，不影响等级。
- **连续打卡** = 最近连续有已通过记录的自然日天数；今天尚未打卡时从昨天往前算。
- 验收：兑换后余额减少但等级不变；调整积分必须填写备注且出现在流水中；余额不会因重复审核重复增加，也不会被调整为负数或低于已锁定积分。

### FR-08 奖励商店（P0）

- 家长创建奖励：名称、emoji、描述、标价、单位（元 / 分钟 / 次 / 分）、兑换倍率、库存（`-1` 表示不限）。
- **所需积分 = ceil(标价 × 倍率)**；倍率默认 `1.0`，`>1` 表示比基准更贵，`<1` 表示更便宜。
- 固定积分奖励可直接把单位设为"分"、倍率设为 `1.0`，此时标价即积分。
- 孩子申请兑换时校验：奖励启用、库存不为 0；普通奖励要求**可用余额**足够，长期心愿要求**可用余额 + 该心愿锁定积分**足够。
- 申请生成"待审核"记录，**此时不扣分**；记录提交时的 `cost_points` 与倍率快照。
- 家长通过时再次校验可用余额（长期心愿同时校验锁定积分），按快照扣分、减库存；驳回不扣分。
- 通过后家长可标记"已兑现"（线下给到孩子）。
- 验收：可用余额不足无法申请（长期心愿按可用余额 + 锁定积分校验）；审批后余额正确；库存为 0 时无法兑换；驳回后余额不变；家长修改倍率不影响已提交的申请。
- 孩子提交的心愿经家长定价后，作为奖励出现在商店（见 FR-18）。

### FR-09 孩子首页（P0）

- 展示：头像与称呼、心愿罐可视化（积分/等级进度）、当前积分、可用积分、锁定积分、累计获得、连续天数。
- 今日任务列表：任务名、分值、类型、所属目标、状态（未完成 / 待确认 / 已完成 / 被驳回）、打卡入口。
- 目标进度列表：进行中优先，显示已得 / 目标积分和进度条。
- 长期心愿入口：显示已存入 / 目标积分、预计完成天数；可进入详情锁定积分。
- 最近 10 笔积分变动。
- 验收：完成打卡后刷新可见状态与积分变化；驳回原因可见；每日任务次日恢复为未完成。

### FR-10 家长看板（P0）

- 展示待审核打卡、待审批兑换、已通过待兑现奖励。
- 展示每个孩子的当前积分、可用积分、锁定积分与本周获得积分。
- **快速代记入口**：选择孩子后展示今日任务，一键完成并加分（见 FR-17）。
- 支持快速调整积分。
- 可查看孩子的心愿储蓄并执行解锁（见 FR-20）。
- 验收：处理任一条目后列表实时更新；各孩子数据正确；从看板完成一项任务不超过 5 秒。

### FR-11 管理页（P0）

- 四个 Tab：成员、目标、任务、奖励；P1 增加"心愿"待处理项。
- 奖励编辑支持标价、单位、倍率、是否长期心愿；可查看并解锁该奖励的储蓄。
- 支持新增、编辑关键字段、启用/停用。
- 验收：改动后孩子端即时生效。

### FR-12 通知（P2，暂缓）

> 目前没有确定的通知渠道，第一版不做通知；以下为后续方案，确认渠道后实施。

- 家长侧通知：
  - 孩子提交打卡后提醒；
  - 每晚固定时间汇总"今天还有 N 项未完成"；
  - 兑换申请提醒。
- 渠道：Bark、企业微信群机器人、Telegram（至少支持一种，可配置）。
- 孩子无设备，不发送孩子侧通知。
- 验收：配置渠道后可收到对应消息；关闭开关后不再发送。

### FR-13 数据备份与迁移（P0）

- 每日自动备份 SQLite 数据库到 `/data/backups`，保留 14 份。
- 备份失败需有日志可查。
- 数据库结构变更通过迁移脚本执行，升级镜像不丢数据。
- 验收：手动触发备份生成文件；恢复备份后可正常登录并看到原数据。

### FR-14 部署（P0）

- 单容器镜像，前端静态文件由后端托管，仅暴露一个端口。
- `docker compose` 运行于群晖 Container Manager；`8080 → 3000`，数据卷 `/data`。
- 启动时自动执行数据库迁移；首次启动进入初始化向导（见 FR-16），开发环境可写入示例数据。
- 验收：群晖上一条 compose 启动成功；重启容器数据不丢；局域网内手机可访问。

### FR-15 移动端适配（P0）

- 采用响应式网页，手机浏览器直接访问，不依赖安装 App 或 PWA。
- 移动端优先，重点适配 Android Chrome；桌面 Chrome / Edge 正常访问。
- 不支持离线写入；断网时展示提示。
- 验收：Android Chrome 打开网址即可完成主要操作；桌面 Chrome 正常访问；iOS Safari 作为可选兼容项，不作为验收条件。

### FR-16 首次启动向导（P0）

- 家庭首次启动时进入向导，不预置虚构成员数据。
- 步骤：家庭名称 + 第一位家长（姓名、头像、PIN）→ 添加孩子（可跳过）→ 选择是否创建示例目标与奖励（默认不创建）。
- 向导完成后进入家长看板；后续可在管理页继续添加成员。
- 开发/演示环境可通过脚本写入示例数据，与正式首次启动分开。
- 验收：全新数据库启动后只能先完成向导；完成后可正常登录；不会出现"小明"等示例成员。

### FR-17 家长快速代记（P0）

- 家长看板提供"今天要完成的事"入口，按孩子分组展示当日适用任务。
- 对任一任务可一键完成：默认免备注、免照片；任务要求照片时需先上传。
- 代记由家长发起，**立即通过并加分**，不进入审核队列。
- 误操作通过积分调整纠正（备注必填），任务状态由家长决定是否驳回。
- 验收：从进入看板到完成一项任务不超过 5 秒；孩子端状态和积分同步更新。

### FR-18 孩子许愿（P1）

- 孩子可以提交心愿：名称、emoji/图片（可选）、想要的理由、期望积分（仅参考）。
- 家长看到待处理心愿后，可设置标价、单位、倍率、库存并上架为奖励，或驳回并填写原因。
- 上架后的心愿与普通奖励一致，进入奖励商店兑换流程。
- 孩子可查看自己提交的心愿及状态（待定价 / 已上架 / 已驳回）。
- 验收：孩子提交后家长端出现待处理项；家长定价上架后孩子端可见并可兑换；驳回原因可见。

### FR-19 奖励兑换倍率（P0）

- 采用方案 B（成本倍率）：`所需积分 = ceil(标价 × 倍率)`。
- 倍率默认 `1.0`，创建奖励时灵活设置：
  - `1.0` 为基准（如电脑：5000 元 × 1.0 = 5000 分）；
  - `>1` 表示该奖励比基准更贵（如现金：100 元 × 1.5 = 150 分）；
  - `<1` 表示比基准更便宜（如书：100 元 × 0.8 = 80 分）；
  - 游戏时间等同理，如 60 分钟 × 1.2 = 72 分。
- 倍率按奖励单独设置，不做全局固定值；P1 再评估按奖励分类提供默认倍率。
- 孩子端展示最终积分价与倍率含义（如“100 元 → 150 分，1.5 倍”）；家长端展示该奖励的实际支出或时间成本。
- 若孩子有进行中的长期心愿，兑换其他奖励时按该心愿的倍率提示影响（如电脑 1.0 时，“换 100 元现金需要 150 分；这 150 分留给电脑值 150 元”）。
- 兑换申请提交时快照 `cost_points` 与倍率，之后家长修改倍率不影响已提交的申请。
- 验收：修改倍率后新申请按新价格；已提交申请按快照价格；孩子端与家长端显示一致。

### FR-20 长期心愿与锁定储蓄（P0）

- 家长可将奖励标记为“长期心愿”；高积分奖励（如 5000 元电脑）建议标记为长期心愿。
- MVP 的长期心愿只做**进度、预计完成天数、锁定储蓄**；家长配捐、奖励专属任务、里程碑 / 分段兑现后置 P1。
- 长期心愿详情展示：目标积分、已存入、剩余积分（目标 − 已存入）、进度条、预计完成天数。
- **预计完成天数**：取最近 14 天（长期心愿优先 30 天，数据不足时按实际天数）的日均获得积分；`预计天数 = ceil(剩余积分 ÷ 日均)`。数据不足 3 天时提示“再记录几天就能预估”；日均为 0 时提示“完成一个任务就能开始预估”。
- 预计天数用“约 X 周 / X 个月”展示，不承诺精确日期；高积分长期心愿可能持续数月到一年以上，MVP 用进度、预计天数和锁定储蓄维持动机，P1 再评估配捐、专属任务和里程碑。
- **锁定储蓄**：孩子可把可用积分存入某个长期心愿；存入后不可用于其他奖励。
- `可用余额 = 余额 − 已锁定积分`；锁定 / 解锁不改变积分余额，只改变可用余额，并写入储蓄记录。
- **解锁由家长操作**；孩子不能自行解锁。MVP 不做孩子申请解锁的流程。
- 兑换长期心愿时，优先消耗该心愿的锁定积分，不足部分使用可用积分；兑换成功后对应锁定记录标记为已兑换；锁定积分超过应付积分的部分退回可用余额。
- 删除或停用长期心愿前必须先释放全部锁定积分，否则拒绝操作。
- 验收：锁定后可用余额减少、余额不变；其他奖励无法使用锁定积分；解锁后可用余额恢复；兑换长期心愿时锁定积分被正确消耗；预计天数在数据不足时有明确提示。

## 6. 关键业务规则汇总

| 规则 | 定义 |
|---|---|
| 积分余额 | 流水求和，实时计算 |
| 等级 | `累计获得 // 100 + 1`，兑换不降级 |
| 审核 | 家长代操作或成员关闭审核时免审 |
| 快速代记 | 家长从看板一键完成，立即通过并加分 |
| 手动调整 | 备注必填；调整后余额不能为负，且不能低于已锁定积分 |
| 首次启动 | 初始化向导，不预置虚构成员 |
| 周期键 | 每日 = 本地日期；每周 = ISO 周；一次性 = `once` |
| 驳回重提 | 复用同周期记录，重置为待审核 |
| 兑换扣分时机 | 家长审批通过时，而非孩子申请时 |
| 奖励倍率 | 方案 B：`所需积分 = ceil(标价 × 倍率)`；1.0 为基准，>1 更贵，<1 更便宜 |
| 倍率快照 | 兑换申请提交时记录 `cost_points` 与倍率，之后改价不影响已提交申请 |
| 可用余额 | `余额 − 已锁定心愿储蓄` |
| 锁定储蓄 | 只用于对应长期心愿；解锁由家长操作；兑换时优先消耗 |
| 预计天数 | 最近 14 天日均（长期优先 30 天，不足按实际）；`ceil(剩余 ÷ 日均)` |
| 库存 | `-1` 不限；审批通过时减 1 |
| 照片 | JPG/PNG/WebP ≤ 5MB，仅存本地 |
| 时区 | 家庭时区，默认 `Asia/Shanghai` |
| PIN | 固定 4 位数字，scrypt 哈希存储 |

### 12.2 后续可调整（不阻塞 MVP）

以下不是 MVP 阻塞项，开发中按当前默认值实现，后续根据实际使用调整。

- 孩子许愿的具体交互：是否允许上传图片、家长定价时是否需要写理由、单次心愿数量限制。

- 通知渠道（以后需要时再定）。

- 储蓄解锁流程：MVP 只做家长直接解锁；是否增加孩子申请 + 家长确认，P1 再定。
- 其他想法已记录，按优先级排期。
